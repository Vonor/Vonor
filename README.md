## What I deliver

- **Better CI/CD around me.** I advise development leads on pipelines and releases.

## Config as code: Git is the single source of truth

If it isn't in the repo, it doesn't exist, and if the running system disagrees with the repo, the system is wrong.

- **Edit in Git, never on the host.** Changes are made in the repo and rolled out by a workflow, so environments can be rebuilt on demand.
- **No PII in plain text.** Personal data such as alerting contacts lives in secrets and variables and is injected when the config is generated. A person is defined once, and every group and notification path resolves to that name.
- **Every change is a reviewed commit.** No late-night edits on a server: every change is a diff, reviewed before it ships and reverted when it's wrong.

## How I learn: build it, then defend it

I learn by doing, not from books: a real project, dirty hands, trying things out. I apply best practices, but I want to understand them well enough to form an opinion and defend it: why this approach, what it costs, where it bites. If the other approach is better, I learn something. If mine is, I have to be able to say exactly why.

My homelab is where that happens. I build, tear down and rebuild, and many stacks came before the current generation, from plain Linux to private clouds. Today it lives in [`kairos-configs`](https://github.com/fam-melcher/kairos-configs) and [`kairos-gitops`](https://github.com/fam-melcher/kairos-gitops). It's also why I'd rather walk people through a live repo than a slide deck.
